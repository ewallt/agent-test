All work should be handled by means of skills. Before executing any multi-step or repeatable task, check whether a skill exists for it. If one does, invoke it. If one doesn't, ask Tom whether to build one first before proceeding.

**Why:** Tom explicitly established this as the governing principle for session behavior. Skills manage the "how"; reference documents carry the "what". Executing directly from memory or documents — bypassing skills — leads to drift, missed steps, and improvised decisions that should be codified.

**How to apply:**
- Before executing any non-trivial task, check whether a skill exists for it — even if you don't already know one does. The check is the habit.
- If a skill exists and is already in context from this session, proceed. If not, read it first.
- Never proceed from memory on a task that could have a skill.
- If a task looks like it will be done more than once and no skill exists, say: "This looks like something we'll do again — should I build a skill for it first?"
- Don't block on this — if Tom says just do it, do it. But the prompt ensures skills stay ahead of repeated manual execution.

Ticket Board

How pending work is tracked, how to read it, and how Claude manages it.

🗂️ Overview

The ticket board is a lightweight Jira-style system for tracking pending work across all projects. It replaces the old memory/pending.md approach — tickets live in a structured JSON file, rendered as a visual board in the browser.

Source of truth: tools/tasks.json

Board UI: tools/tasks.html — served at localhost:3010/tasks.html

Claude manages the JSON directly. The board reflects changes on the next refresh. There's no database, no server-side logic — just a JSON file and a static HTML page.

📄 Ticket Structure

Each ticket is a JSON object inside a group → workflow hierarchy:

{ "id": "bcr-2", "title": "UsCities pacing fix", "notes": "Simultaneous engine goes too fast — only 13 decennial periods.", "priority": 3, "status": "pending" }
id
Unique identifier. Prefix + sequential number (e.g. bcr-2, nlm-5).
title
Short description of the work item.
notes
Context, links, design decisions — whatever Claude or Tom needs to pick the ticket back up.
priority
1 (critical) → 5 (backlog). Most tickets are P3. Shown as a coloured badge on the board.
status
See statuses below.

🚦 Statuses

pending in-progress done blocked
pending
Open, not yet started. The default state for new tickets.
in-progress
Actively being worked on this session or recently started.
done
Completed. Shown as struck-through on the board and excluded from summary counts.
blocked
Waiting on something external — a decision, a dependency, input from Tom.

🏷️ ID Prefixes

Ticket IDs follow a prefix-N pattern. Each group owns a prefix; numbers are assigned sequentially.

🗃️ JSON Structure

The full file is a nested hierarchy: groups → workflows → tasks.

{ "groups": [ { "id": "remotion", "label": "Remotion", "workflows": [ { "id": "bar-chart-race", "label": "Bar Chart Race", "tasks": [ ... ] }, { "id": "whiteboard-explainer", "label": "Whiteboard Explainer", "tasks": [ ... ] } ] }, { "id": "notebooklm", "label": "NotebookLM", "workflows": [ ... ] }, { "id": "infrastructure", "label": "Infrastructure", "workflows": [ ... ] } ] }

The board UI renders groups as section headings, workflows as collapsible sub-panels, and tasks as rows with a status dot, title, and priority badge. Clicking a task expands its notes.

🤖 How Claude Manages Tickets

Claude uses the ticket-tracker skill to read and update tasks.json. The skill is triggered by:

— Mentioning "jira" or "ticket"
— Referencing a ticket ID (e.g. "what's the status of bcr-2?")
— Asking what's open, pending, or in progress
— Saying things like "mark that done" or "add a ticket for X"
— During shutdown (Step 4), to sync statuses from what was worked on

No manual JSON editing needed Just tell Claude what to update in plain English. It reads tasks.json, makes the change, and writes it back.

Things Claude can do

Show open tickets
Lists all pending and in-progress tickets grouped by workflow.
Update status
Changes the status field on any ticket by ID or description.
Add a ticket
Appends a new task to the right group/workflow, assigns the next ID in sequence.
Show a ticket
Displays title, notes, status, and priority for a specific ticket.
Shutdown sync
Reviews what was worked on and updates statuses automatically at session end.

📜 History

The ticket system replaced memory/pending.md on 2026-03-12. The old file is kept as a historical archive but is no longer updated. All new pending items go into tasks.json as tickets.

The board UI (tasks.html) pre-existed the formal ticket skill — it was originally a simple task tracker. The ticket-tracker skill and the done/blocked statuses were added at the same time as this consolidation.

Session Strategy

How the approach to permissions, context, and session management evolved — and what the current setup looks like.

⚠️ The Problem

Claude Code's default behavior is to prompt for permission on every file write, edit, and shell command. Out of the box this means constant interruptions — approving reads, writes, and git commands one by one. The other pressure point is context: Claude is stateless across sessions, so every new session starts cold unless something carries context over.

The early strategy addressed both problems but did so bluntly. The current strategy is more surgical — handling permissions through configuration and context through compaction rather than session boundaries.

🔄 The Two Eras

Era 1  Manual Session Management
  • Permissions: --dangerously-skip-permissions flag — all prompts bypassed, no guardrails
  • Compaction: threshold at 95% — effectively never compacted mid-session
  • Session boundaries: used deliberately as a context management tool — start fresh to control what carries over
  • Context bridge: shutdown task writes a handoff; startup task reads it back at session start
  • Philosophy: session breaks are how you reset; manage drift by ending sessions, not by staying in them
Era 2  Current Approach
  • Permissions: defaultMode: auto + explicit allow list + CLAUDE.md guardrails — surgical, not blunt
  • Compaction: threshold at 50% — compaction happens mid-session; sessions can run longer
  • Session boundaries: matter less now; compact-and-continue replaces end-and-restart
  • Context bridge: /pre-compact logs before compacting; /post-compact re-reads orientation files after
  • Philosophy: sessions are long-running; manage context within them through compaction, not by breaking them

🔐 Permissions

Why not --dangerously-skip-permissions?

The flag works but bypasses everything — including actions that genuinely warrant a pause. It also requires passing it on every CLI invocation, which is fragile. defaultMode: auto uses Claude's own judgment (the LLM classifier) to decide what needs approval, which is a better fit than an all-or-nothing bypass.

Current settings.json

{ "env": { "CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "50" }, "permissions": { "allow": [ "Bash(*)", "Write", "Edit" ], "defaultMode": "auto" }, "skipAutoPermissionPrompt": true, "skipDangerousModePermissionPrompt": true }

Bash(*) allows all shell commands without prompting. Write and Edit are in the allow list so file operations never prompt. The actual guardrails live in CLAUDE.md, not the harness.

CLAUDE.md as the real guardrail

The four actions that still require confirmation before proceeding:

  • Deleting a NotebookLM notebook
  • Force-pushing or hard-resetting git history
  • Committing directly to main
  • Permanently deleting files outside the git repo

Everything else proceeds without asking. The philosophy: Claude's judgment via CLAUDE.md instructions is a better filter than harness prompts for routine work.

🧠 Context Management

Era 1: Session as context boundary

Sessions were kept short and broken deliberately. The shutdown task wrote a handoff file summarizing what happened; the startup task read it back. The session boundary was a tool — a forced reset that gave you control over what context the next Claude instance would start with.

The cost: friction at every session start, loss of conversational continuity, and dependence on handoff quality. If the handoff missed something, that context was gone.

Era 2: Compaction within sessions

Auto-compact fires at 50% context usage (down from 95%). This means sessions can run much longer without hitting the limit, and compaction is a mid-session tool rather than a near-crash event.

Two skills handle the manual compact flow:

  • /pre-compact — writes a session log entry while context is fresh, then prompts you to run /compact
  • /post-compact — after compaction, re-reads overview.md, the session log (recent entries), and MEMORY.md to restore orientation

The session log is the durable record. Rather than relying on a handoff written at session end, context is captured incrementally throughout the session as work completes.

The key shift Era 1 managed statefulness by controlling when sessions ended. Era 2 manages it by what gets written to durable files throughout a session — and by re-reading those files after compaction restores a clean context window.

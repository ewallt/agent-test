# Bar Chart Race — Refactoring Record

## What Was Refactored

The original bar chart race was a single-composition project — all data and rendering logic
were bundled together in one file. The refactor separated the generic rendering engine from
project-specific content, making it trivial to add new bar chart races without touching any
code.

---

## Before (v0.1 — see legacy/)

- One file (`BarChartRace.tsx`) contained both the renderer and the data
- Adding a new topic meant copying and modifying the whole file
- No separation between "the program" and "the content"

---

## After (current architecture)

### The engine (`src/`) — never changes

| File | Purpose |
|------|---------|
| `src/engine/BarChartRace.tsx` | Generic React component — renders any bar chart race |
| `src/engine/compute.ts` | Pure stateless functions: keyframes, card scheduling, frame counts |
| `src/engine/types.ts` | Shared TypeScript types |
| `src/index.tsx` | Remotion entry point — registers all compositions |

### The library (`library/`) — shared constants

| File | Contents |
|------|---------|
| `library/timing.ts` | `standardTiming` — fps, topN, transitionFrames, holdFrames, trailingFrames |
| `library/music.ts` | `signalThroughTheDark` — MP3 filename and volume |
| `library/colors.ts` | Named color palettes (palette5, palette6, palette7, palette10) |

### The data (`data/{project}/`) — one folder per bar chart race

Each project folder contains four component files:

| File | Contents |
|------|---------|
| `entries.ts` | The data points — model, lab, date, value |
| `categories.ts` | Lab name → hex color mapping |
| `metadata.ts` | id, title, valueSuffix |
| `story-cards.ts` | Narrative cards — trigger, title, body |

Plus a fifth generated file:

| File | Contents |
|------|---------|
| `barchart.ts` | Assembled config — generated by `npm run build`, do not edit manually |

### The build script (`scripts/build.ts`)

Assembles the four component files plus library constants into a single `barchart.ts`.
Also writes a copy to `staging/{project}.ts`.

```
npm run build -- {project-name}
```

---

## Workflow for a New Bar Chart Race

1. Create `data/{project}/` with the four component files
2. Run `npm run build -- {project}` — generates `barchart.ts` and `staging/{project}.ts`
3. Add an import and entry to `src/index.tsx`
4. `npm start` → preview at localhost:3000
5. `npm run render` → produces MP4

No files in `src/engine/` or `library/` need to change.

## Notes

- The `active/` folder and `src/active-config.ts` are present but not currently used —
  `index.tsx` imports projects directly. The design doc describes a one-at-a-time activation
  pattern; the current approach renders all projects simultaneously (preferred).
- `src/registry.ts` is orphaned dead code — `index.tsx` is the real registration point.
- The `legacy/` folder preserves the original v0.1 code for reference.

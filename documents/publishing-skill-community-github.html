Publishing a Claude Code Skill to the Community

A practical reference for what to do if a strong custom skill gets built and is ready to share publicly.

The simplest path is to create the skill locally, test it, put it in a public GitHub repository, and then make it discoverable through one or more community directories.

Practical Path

1. Build the skill in standard form

The common requirement is a valid SKILL.md file. Public directories also expect a concise description and usually a README or other basic documentation.

At minimum, have:

  • SKILL.md
  • README.md
  • Optional examples or demo files
  • Optional scripts if the skill needs them

2. Test it locally first

The safest first step is to place the skill under a local Claude skills folder, verify that it loads, and make sure the behavior is actually useful before publishing anything publicly.

.claude/skills/<skill-name>/SKILL.md

3. Put it in a public GitHub repo

A public repo is the key distribution unit. Once the repository is public and structured correctly, others can install the skill from GitHub.

A clean repo can be very simple:

my-skill-repo/
  SKILL.md
  README.md

Or, if there are multiple related skills:

my-skills/
  whiteboard-explainer/
    SKILL.md
  remotion-doodle/
    SKILL.md
  README.md

4. Make sure install works

Before trying to list the skill anywhere, verify that someone can install it cleanly from the command line. This is the practical test that matters most.

5. Get it listed in a directory

This is what people often mean by “getting it into a community GitHub,” but in practice there is no single universal master repository. There are multiple directories and marketplaces.

The usual pattern is:

  1. Publish the repo
  2. Verify installation
  3. Submit it to one or more directories

Main Places to List It

skills.sh ecosystem

This is one of the most visible parts of the current ecosystem. Installs are tracked automatically, and skills can show up on leaderboards once people start using them.

Claude Skills Directory

This directory uses a submission process with metadata and review. It is a more curated listing path.

Skillstore

This is another listing path that emphasizes review and security checks before public listing.

Important: “Community GitHub” usually means publishing the skill on GitHub first and then listing it in one or more public directories. It usually does not mean there is one giant shared repo where all skills live.

Shortest Version

  1. Create SKILL.md
  2. Test it locally in .claude/skills/...
  3. Push it to a public GitHub repo
  4. Verify that the install command works
  5. Submit the repo to a directory such as Claude Skills Directory or Skillstore
  6. Let installs accumulate so it becomes easier to discover

Good Extras Before Publishing

  • A permissive license such as MIT or Apache 2.0
  • Clear examples in the README
  • Warning notes if the skill runs shell commands
  • Precise trigger language in the description
  • A small demo or sample workflow

Best Approach for a Specialized Skill

For a skill that serves a specialized use case, the cleanest launch is usually:

  • Start with one public repo
  • Include one polished skill
  • Make the README concrete and example-driven
  • Test installation from scratch
  • Submit to only one or two directories at first

This avoids a messy launch and makes it easier to improve the skill based on early feedback.

Example First Release Shape

  • Repo name: whiteboard-explainer-skill
  • Contains SKILL.md and README.md
  • Installation tested directly from GitHub
  • Submitted to a directory
  • Direct GitHub install command shared publicly

Later, if the project grows, related skills can be bundled into a broader multi-skill repo.

One Caution

Community directories are not all the same. Some are simple indexes, some review submissions, some track installs, and some perform security review. So the real process is usually:

GitHub first, directory listing second.

This page is intended as a practical reference note for future use if a strong skill is created and ready to publish.

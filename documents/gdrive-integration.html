Google Drive MCP Integration

Read and write Google Docs from Claude Code using the official Drive MCP server — enabling a full round-trip with NotebookLM.

← Back to index

🎯 The Goal

Close the loop between NotebookLM and Google Drive. The round-trip looks like this:

NotebookLM generates Report
→
nlm export to-docs
→
Google Drive Doc
→
Claude reads via MCP
→
Claude writes back as new source

This lets Claude augment, edit, or reformat NotebookLM output and feed it back into a notebook as a new source — all without manual copy/paste.

🔌 The MCP Server

Package: @modelcontextprotocol/server-gdrive — the official Google Drive MCP server from the Model Context Protocol project. It handles OAuth token refresh automatically and translates between Google's native formats and plain text.

Add this block to ~/.claude.json under mcpServers:

{ "mcpServers": { "gdrive": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-gdrive"], "env": { "GDRIVE_CREDENTIALS_PATH": "<ABSOLUTE_PATH_TO_HOME>/.notebooklm-mcp-cli/gcp-oauth.keys.json" } } } }
Credentials path The gcp-oauth.keys.json file lives in ~/.notebooklm-mcp-cli/ — the same directory the nlm tool uses for its auth state. It may already exist from the NotebookLM setup.

🔐 Authentication & OAuth Scope

Pattern: User-delegated OAuth 2.0. A one-time browser login mints a token.json file containing a long-lived refresh token. After that, the MCP server handles token refresh silently — no browser popups during Claude Code execution.

Required scope: https://www.googleapis.com/auth/drive (full Drive access).

Do not use drive.file scope The restrictive drive.file scope only permits access to files the application itself created. Because this workflow reads docs that Tom drafts manually in the Google Docs UI, full drive scope is required — otherwise file discovery will fail silently.

The OAuth credentials are generated in Google Cloud Console: create a project, enable the Drive API and Docs API, set up an OAuth consent screen (External, add your account as a test user), and create a Desktop App Client ID. Download the resulting JSON as gcp-oauth.keys.json.

📖 Reading Google Docs

Pass the document ID to the Drive MCP. The MCP handles the format conversion automatically.

Native .gdoc files are metadata pointers, not byte streams On disk, Google Docs exist as small .gdoc JSON pointer files — not actual text. Do not try to parse these locally. When you request a read via the MCP using the document ID, the server calls the Drive export API and returns the human-readable text content.

Get the document ID from the URL: docs.google.com/document/d/<DOCUMENT_ID>/edit

✍️ Writing to Google Drive

Creating a new native Google Doc

Submit Markdown text as the payload with MIME type application/vnd.google-apps.document. The Drive API automatically parses the Markdown and converts it into a richly formatted native Google Doc — headings, bold, lists, and all.

# MIME type tells Drive to convert Markdown → native Doc mimeType: application/vnd.google-apps.document payload: <raw Markdown string>

Updating existing docs — use versioned files instead

Appending to an existing native Google Doc requires complex batchUpdate operations via the Docs API. Don't do this. For iterations, create a new discrete file with a version suffix:

Doodle_Script_v1 ← original Doodle_Script_v2 ← revised by Claude Doodle_Script_v3 ← further iteration

📓 NotebookLM Side: Exporting to Drive

Use nlm export to-docs to push a Report artifact from NotebookLM into Google Drive as a native Doc. First get the artifact ID from nlm studio status.

# Step 1: Find the artifact ID PYTHONIOENCODING=utf-8 nlm studio status <notebook-id> # Step 2: Export to Google Docs PYTHONIOENCODING=utf-8 nlm export to-docs <notebook-id> <artifact-id> --title "My Report"

Works with: Briefing Doc, Study Guide, Blog Post, and other Report-type artifacts. For Data Tables, use nlm export to-sheets instead.

🛠️ Setup Steps

1

API Provisioning

In Google Cloud Console, create or select a project. Enable both the Google Drive API and the Google Docs API.

2

Credential Generation

Configure the OAuth consent screen (External; add your Google account as a test user). Under Credentials, create an OAuth 2.0 Client ID for a Desktop app. Download as gcp-oauth.keys.json and place in ~/.notebooklm-mcp-cli/.

3

Token Minting

Run the MCP server's init script locally. It opens a one-time browser session using the credentials file. After you grant permission, it writes a token.json containing the long-lived refresh token. This is the only time a browser is needed.

4

MCP Configuration

Add the gdrive block to ~/.claude.json with GDRIVE_CREDENTIALS_PATH pointing to the absolute path of gcp-oauth.keys.json. Restart Claude Code.

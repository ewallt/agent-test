Reference Guide

Bar Chart Race

How the engine works, how the data is structured, and how to wire up a new dataset.

⬡ Architecture — Engine vs. Data

The project is split into two permanent layers that never mix: a generic engine that knows how to render any bar chart race, and per-project data files that supply everything domain-specific. You never touch the engine to add a new project.

bar-chart-race/ src/ ← engine — never changes index.tsx ← registers all compositions engine/ BarChartRace.tsx ← generic renderer compute.ts ← pure computation types.ts ← shared TypeScript types data/ ← one folder per project ai-mmlu/ entries.ts ← raw data rows categories.ts ← lab → color map metadata.ts ← id and title story-cards.ts ← narrative cards barchart.ts ← generated output (imported by engine) streaming-wars/ ← same structure tallest-buildings/ ← data exists, not yet wired up library/ ← shared defaults timing.ts ← standardTiming constants music.ts ← music track references colors.ts ← palette5 / palette7 / palette10 staging/ ← build output, pre-activation completed/ ← archived after render

The engine's entry point, src/index.tsx, imports each project's barchart.ts and registers it as a Remotion composition. Adding a new project means adding two lines there — nothing else in src/ changes.

⚙ How the Engine Works

compute.ts — pure functions, no React

Before any frame is drawn, compute.ts derives everything the renderer needs from the config. Three key functions:

buildKeyframes(config)

Sorts entries by date, then produces one Keyframe per entry. Each keyframe records which models are in the top N at that moment, their scores, and the frame number where the keyframe starts.

buildCardSchedule(config, keyframes)

Matches each story card's trigger field (a model name) to its keyframe. Each card runs from its trigger frame until the next card's trigger — no gaps once the first card appears.

computeTotalFrames(config)

Returns entries.length × framesPerEntry + trailingFrames. Remotion needs this upfront to set the composition length.

getConstants(config)

Reads timing params from the config (or applies defaults). Returns topN, fps, transitionFrames, holdFrames, and the derived framesPerEntry.

Animation model

Every entry gets a two-phase keyframe:

Transition (default 25 frames)

Bars animate to new widths and positions. New entries slide in from below; entries that drop out of the top N slide away downward.

Hold (default 20 frames)

Everything pauses. The new bar has appeared, the date updates, and the story card (if any) is fully visible before the next entry arrives.

At 30 fps, each entry takes 45 frames = 1.5 seconds. A dataset of 35 entries runs about 53 seconds before the trailing hold.

BarChartRace.tsx — the renderer

A React component that receives the full config as props. On each frame it calls compute.ts to get the keyframes, finds the current and previous keyframe, and interpolates bar positions and widths using Remotion's interpolate(). It renders bars, rank numbers, the date display, story cards, legend, and background music — all in one component. You never need to touch it.

≡ BarChartConfig Reference

Every project exports a single data object of this type. Required fields first, then optional.

FieldTypeDescription
id required Remotion composition ID — must be unique across all projects. Used in the URL and render command. Example: AiMmlu
title required Displayed in the video header.
entries required Array of ModelEntry. Each has model (bar label), lab (category — must match a key in labColors), date (YYYY-MM-DD), mmlu (the numeric score — legacy field name used for all projects), and optional estimated: true which renders a ~ prefix on the value.
labColors required Map of lab name → hex color string. Every lab name that appears in entries must have an entry here.
storyCards required Array of narrative cards. Each has trigger (a model value — the entry whose keyframe starts this card), title, and body. Cards without a matching trigger are silently ignored.
topN optional How many bars to show at once. Default: 10.
fps optional Frames per second. Default: 30.
transitionFrames optional Frames spent animating each new entry. Default: 25.
holdFrames optional Frames to pause after each transition. Default: 20.
trailingFrames optional Extra frames appended after the last entry — a final hold. Default: 0. Standard timing uses 60 (2 seconds).
musicSrc optional Filename of an MP3 in public/. Resolved via Remotion's staticFile().
musicVolume optional Volume 0–1. Default: 0.7.
valueSuffix optional Suffix shown after each score. Default: %. Change to M, K, etc. for non-percentage data.

+ Adding a New Dataset

A new project is entirely self-contained in a new data/{project}/ folder. The build script assembles the component files into the final barchart.ts that the engine imports.

Step 1 — Create the four component files

Create data/{project}/ and write these four files:

metadata.ts

export const metadata = { id: 'MyProject', // Remotion composition ID — no spaces title: 'My Bar Chart Race', };

categories.ts

import { palette7 } from '../../library/colors'; export const categories: Record<string, string> = { CategoryA: palette7[0], // teal CategoryB: palette7[1], // red // or use hex directly: CategoryC: '#f97316' };

entries.ts

import { ModelEntry } from '../../src/engine/types'; export const entries: ModelEntry[] = [ { model: 'Item A', lab: 'CategoryA', date: '2020-01-01', mmlu: 42.0 }, { model: 'Item B', lab: 'CategoryB', date: '2020-06-15', mmlu: 67.5 }, // Entries can be in any order — the engine sorts by date // estimated: true adds a ~ prefix to the displayed value ];

story-cards.ts

import { StoryCard } from '../../src/engine/types'; export const storyCards: StoryCard[] = [ { trigger: 'Item A', // must exactly match a model name title: 'The story begins', body: 'Narrative text shown from this entry until the next card.', }, ];

Step 2 — Run the build script

From the bar-chart-race/ directory:

npm run build -- my-project

This reads the four component files, merges them with the standard timing defaults and default music track, and writes two files:

✓ Built data/my-project/barchart.ts ← permanent archive copy ✓ Staged staging/my-project.ts ← ready to activate

Step 3 — Register it in data/index.ts

Open data/index.ts and add your project:

import { data as myProject } from './my-project/barchart'; export const configs = [aiMmlu, streamingWars, myProject];

src/index.tsx never changes — it just imports configs from here. The engine registers a Remotion composition for every entry in the array.

Step 4 — Preview and render

1
npm start Opens Remotion Studio at localhost:3000. Your new composition appears in the sidebar alongside the existing ones. Scrub through it to check timing and story cards.
2
Render Run npx remotion render MyProject out/my-project.mp4 directly (the npm run render script is hardcoded to AiMmlu — use the CLI directly for other projects).
3
Archive Once rendered, move the staged file from staging/ to completed/. The data/{project}/ folder stays as the permanent source.
Note on the mmlu field name: The ModelEntry type uses mmlu as the score field — a legacy name from the first project. It's just a number and works for any domain (subscriber counts, building heights, etc.). Use valueSuffix in the config to control how it displays.

📚 Library Defaults

The library/ folder holds shared constants used by the build script. You can override any of these in the config, but the build script applies them automatically as defaults.

timing.ts — standardTiming

fps: 30 | topN: 10 | transitionFrames: 25 | holdFrames: 20 | trailingFrames: 60

music.ts — signalThroughTheDark

The default background music. Points to Signal Through the Dark.mp3 in public/, volume 0.7. Override musicSrc in the config to use a different track (add the MP3 to public/ first).

colors.ts — palettes

Four ready-made palettes: palette5, palette6, palette7, palette10. All share the same ordered set of colors — teal, red, blue, eggshell/eggshell-white, purple, orange, yellow, pink, cyan, lime. Use palette indices in categories.ts for consistent color assignment, or use hex strings directly.

### Install command reality check

The skills CLI (“npx skills”) supports:
- `npx skills add owner/repo` (GitHub shorthand), or a full GitHub URL
- `--skill <name>` to install a specific skill
- `-g` for global install and `-y` to skip prompts
- `-a claude-code` to target Claude Code specifically (optional but useful) citeturn0search2turn7view1

So the correct pattern for what you requested is:

```bash
npx skills add <owner/repo-or-url> --skill <skill-name> -g -a claude-code -y
```

This matches the CLI’s documented flags (`-g`, `-y`, `--skill`, `-a`). citeturn7view1

## Security scan checklist and what I actually verified

You asked to flag:
- hardcoded credentials
- base64 payloads in scripts/
- instructions to suppress output / hide actions
- `eval()` or dynamic shell execution

What I checked in this environment:

- For `frontend-slides`, I retrieved and scanned `extract-pptx.py` (PPTX extraction) and did not see base64 strings, eval-like behavior, or shell execution patterns; the script reads PPTX via `python-pptx`, writes images, and emits structured JSON. citeturn14view1turn26view3  
- For `revealjs`, I retrieved and scanned `create-presentation.js` and `check-overflow.js`. `check-overflow.js` uses Puppeteer to load a local file URL and checks DOM dimensions; no `eval()` usage was found via text search, and the script content is straightforward automation (launch browser, evaluate sizes). citeturn23view0turn23view1turn22view0turn22view2  
- For `ppt-creator` and `ln-150-presentation-creator`, I could retrieve the SKILL.md content but not all referenced scripts due to intermittent fetch failures. I did not see credential patterns inside SKILL.md itself, and both describe fairly transparent workflows. citeturn14view2turn16view0turn24view2turn25view4  

If you want a “real” security review workflow, the practical advice is:
1) install a single skill (not an entire repo) using `--skill`,  
2) inspect the repo’s `scripts/` directory before running anything,  
3) run automation in a sandboxed directory/project,  
4) avoid skills that instruct you to “hide logs” or “suppress outputs” without a legitimate reason.

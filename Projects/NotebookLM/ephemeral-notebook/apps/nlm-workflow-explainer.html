The Notebook Workflow

Claude Code acts as an orchestrator — it creates a NotebookLM notebook, populates it with sources, triggers artifact generation, reads what NLM produces, and builds a companion web app. You drop a topic; Claude handles the rest.

What Claude Handles Autonomously

🔬 Research

Claude triggers NLM's web research, waits for completion, and imports sources — typically 8–10 current articles found automatically.

💬 Querying

Claude asks the notebook targeted questions and uses the synthesized answers to build content — no copy-paste, no manual handoff.

🌐 Web App

Claude writes a single-file HTML companion app with an Explorer (focus angles + follow-up chips) and a Quiz grounded in the notebook's content.

🎬 Video

Claude triggers NLM's Video Overview generation last — it takes several minutes, so it runs in the background while other work completes.

The key insight

Claude Code is not just a setup script for NotebookLM. It reads what NLM produces and uses that content to build better artifacts. The query mechanism is the bridge that makes this possible.

Claude Code + NLM Setup

Claude Code controls NotebookLM through a command-line tool called nlm — the NotebookLM MCP CLI. All operations go through this tool: creating notebooks, adding sources, generating artifacts, querying, and exporting.

The nlm CLI

⌨️ notebooklm-mcp-cli (nlm)

A Python-based CLI that provides programmatic access to NotebookLM. Claude Code issues commands; NLM executes them against a real notebook in the Google NotebookLM backend. Auth is OAuth-based and sessions last ~20 minutes.

# Always prefix — prevents Unicode errors on Windows
PYTHONIOENCODING=utf-8 nlm notebook create "The Drinker Paradox"
# → Notebook ID: cce55efb-9728-41ec-8ea5-3686f47f9f23

PYTHONIOENCODING=utf-8 nlm research start "Claude Code features 2025 2026" \
  --notebook-id cce55efb --mode fast

PYTHONIOENCODING=utf-8 nlm research import cce55efb <task-id>

PYTHONIOENCODING=utf-8 nlm notebook query cce55efb \
  "What are the main themes and arguments?"

Source Patterns

Three ways to populate a notebook with knowledge:

🌐 Web Research

NLM fetches 8–10 current web sources automatically. Best for recent topics or anything where freshness matters.

🤖 Claude as Source

Claude writes the knowledge base and uploads it as a text file. Best for well-defined topics where Claude's training is sufficient.

📋 Copied Text

Tom pastes in a transcript, document, or article. Claude uploads it. Best for specific source material Tom already has.

📄 File Upload

Local files (markdown, text) uploaded directly as sources. Used when Claude writes a knowledge base or slide manifest that feeds back into the notebook.

Auth and Sessions

Session limit: ~20 minutes

NLM auth sessions expire. Claude checks auth before every run and prompts for re-login when needed. The nlm login command opens a browser flow — takes about 30 seconds.

Google Drive Integration (optional)

NLM can export artifacts directly to Google Drive as native Google Docs. With a separate OAuth setup, Claude can also read those docs — enabling an iterative loop where Claude improves NLM's output and feeds it back in as a new source. Useful for multi-pass refinement of slide manifests, briefing docs, and study guides.

Reading NLM Content

Claude Code can query any NotebookLM notebook directly — asking targeted questions and getting synthesized answers grounded in the notebook's sources. No artifact export needed, no extra setup. Just ask.

How the Query Works

Once sources are imported, NLM has synthesized them into its knowledge graph. A query asks NLM to draw on that synthesis to answer a specific question. The response is grounded in the actual sources — not NLM's general training, and not Claude's training. It's what the sources say.

PYTHONIOENCODING=utf-8 nlm notebook query 4872a2c8 \
  "What are the most recent major features of Claude Code as of 2025-2026?"

# Response (excerpt):
# Recent Features: February – March 2026 (v2.1.69–2.1.71)
# • /loop Command: recurring task feature — "cron for your AI agent"
# • Remote Control: start a terminal session locally, continue from mobile
# • Claude Code Security: built-in codebase vulnerability scanner
# • Version 2.1.0 (Jan 2026): skill hot-reload, context forking, bash wildcards

Why Query Is Better for Web Apps

When Claude builds a web app companion, it needs to populate FOCUS_PROMPTS — dense knowledge paragraphs for each Explorer focus angle. Without querying, Claude guesses from its own training. With querying, Claude gets NLM's synthesis of the actual sources. The difference is especially dramatic for:

📅 Post-Cutoff Topics

Claude's training has a knowledge cutoff. For anything more recent, NLM's web research sources are the only reliable ground truth. Query extracts that knowledge directly.

📚 Niche Books and Works

For a book like Behold Your God by F.T. Wright — a specific work Claude doesn't know well — query gives the actual arguments and illustrations from the text, not guesses.

Why It Matters

The ability to query NotebookLM directly changes what Claude can build. Here are concrete examples where it makes a meaningful difference.

📅 Post-Cutoff Topics new

The problem: Claude's training has a knowledge cutoff (August 2025). Ask Claude to build a web app about "The Current State of Claude Code" in March 2026 and it will guess — and guess wrong about anything released in the last 7 months.

With query: Claude runs NLM web research (10 current sources found automatically), then queries the notebook. The responses include version numbers, feature names, and release dates Claude has never seen. The FOCUS_PROMPTS in the web app are accurate to the actual current state — not Claude's stale memory.

Example query used: "What are the most recent major features and updates to Claude Code as of 2025–2026?" — Response included /loop command, Remote Control, Claude Code Security (v2.1.71), skill hot-reload (v2.1.0), and context forking.

📖 Niche Books and Specific Works new

The problem: Build a web app about Behold Your God: Understanding Divine Character by F.T. Wright — a specific theological book Claude doesn't know well. Without querying, Claude fills FOCUS_PROMPTS with generic theology, missing the book's actual arguments entirely.

With query: Claude queries the notebook loaded with the book's content. The response names every illustrative concept: the Nuclear Power Plant Technician, the Hollywood Western (White Hat/Black Hat), the Father and the Son and the Gun, Rods and Serpents, the Boeing 747 Pilot. Claude builds FOCUS_PROMPTS from the actual book — the AI in the web app elaborates on what the sources say, not what it guessed.

The result: A web app that genuinely knows the book. The Explorer explains Wright's arguments accurately. The quiz asks questions about his specific illustrations, not generic theology.

🎙️ YouTube Video Companions new

The use case: A YouTube video covers a specific topic with a specific angle. The companion web app should match the video's content — not generic background on the topic.

With query: Claude queries the same notebook that grounded the video's content. The focus angles in the Explorer match the video's focus angles. The quiz tests what the video taught, not what Claude thinks is interesting about the topic. The app and the video are coherent because they draw from the same source.

🔁 Iterative Refinement via Google Drive

NLM can export artifacts directly to Google Drive. With the Drive integration enabled, Claude can read those exports, improve them — deepening thin sections, strengthening narrative arcs — and re-upload the improved version as a new notebook source. NLM regenerates from a better brief. This is a separate capability from querying: querying reads NLM's synthesis; Drive export reads the artifact itself and feeds an improved version back in.

The shift in mental model

Before: Claude builds the notebook and NLM generates outputs. Claude never sees what NLM produced.

After: Claude builds the notebook, queries it to read NLM's synthesis, and uses that synthesis to build better outputs. Claude and NLM are collaborators, not pipeline stages.

The bigger picture

Claude Code and NotebookLM are becoming a two-AI system — one that researches and synthesizes (NLM), one that orchestrates and builds (Claude). The query mechanism is what connects them. Tom's role shifts from managing handoffs to setting topics and reviewing finished work.

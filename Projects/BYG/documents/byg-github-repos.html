GitHub Repository Structure

Two-repo design for Behold Your God — dev for active work, prod for what's live.

🗺 Overview

BYG uses two separate GitHub repositories. The split encodes maturity in structure: you know whether something is dev or prod by where it lives, not by trying to remember when it was deployed.

The local agent-test repo is the source of truth for all work. GitHub repos are downstream — they receive what's been built locally, they don't originate anything.

Clean prod URL The prod repo gets the short name byg so the public URL stays clean: ewallt.github.io/byg/. The dev repo takes the longer name byg-dev — its URL is only used internally for review.

🌿 Branch Structure

Each repo has the same two branches, serving different purposes.

Branch Contains Notes
main Full source — everything in main is also on gh-pages, plus the source files that power it Complete record; not publicly served by GitHub Pages
gh-pages Deployable subset — HTML wrapper pages, MP4 videos, the BYG web app Served publicly by GitHub Pages; a curated subset of main
Everything on gh-pages is also in main — not the reverse gh-pages contains only what makes sense to serve publicly. Source files (TSX, scripts, audio) live in main but are not published to gh-pages.

📁 What Goes Where

byg-dev / gh-pages

The rendered outputs for completed illustrations — wrapper HTML pages, MP4 video files, and the BYG web app. This is what's previewed during review before promoting to prod.

byg-dev/gh-pages/ behold-your-god/index.html ← BYG web app byg-nuclear-plant/ index.html nuclear-plant-v5.mp4 byg-god-not-criminal/ index.html god-not-criminal-v1.mp4 byg-white-hat-black-hat/ index.html white-hat-black-hat-v1.mp4 ...

byg / gh-pages (prod)

Same structure as byg-dev, but only what's been deliberately promoted. Starts with just a README. New illustrations are added one at a time, after review on byg-dev.

Local agent-test (not on these repos)

All source files — TSX compositions, generation scripts, audio files, durations, skills, documents. This is never pushed to byg or byg-dev directly. The rendered outputs (HTML, MP4) are what get deployed.

🔄 Promotion Workflow

1. Build locally

Illustration built in agent-test/Projects/Remotion/simple-narrated-slides/. Audio generated, durations measured, TSX composition written. Rendered to MP4 via node render.js.

2. Deploy to byg-dev

Wrapper HTML written, MP4 copied, web app updated. Committed to agent-test dev branch (local backup). Rendered files pushed to byg-dev/gh-pages.

3. Review on byg-dev staging

Tom reviews at ewallt.github.io/byg-dev/. Checks video playback, web app integration, wrapper page. Sign-off required before promotion.

4. Promote to prod

Approved files copied from byg-dev/gh-pages to byg/gh-pages. Prod URL goes live at ewallt.github.io/byg/.

Status is structural You never need to remember what's been promoted. If it's on byg-dev, it's been built and reviewed. If it's on byg, it's prod. The location tells you the status.

🔗 Relationship to agent-test

agent-test is the local git repo backed up to github.com/ewallt/agent-test. It contains everything — all projects, all source, all skills and documents. It is the source of truth.

byg-dev and byg are downstream publication targets. They receive rendered outputs only. They are not forks or mirrors of agent-test — they are separate repos with a different purpose.

The three repos serve three different concerns:

agent-test
Full project backup — source, skills, documents, all projects
byg-dev
BYG staging site — rendered outputs under review
byg
BYG production site — what's officially published
